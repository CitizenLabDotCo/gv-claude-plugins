# Notion page layout (optimize for Notion)

Create ONE page via the Notion MCP (`notion-create-pages`). Use native Notion blocks, not a wall of
text. Write everything in the city's local language. Keep it skimmable and presentable to a client.

## Page title
`[City] — <local: proposed participation programme> <horizon, e.g. 2026–2027>`
e.g. NL: "Oostende — voorgesteld participatieprogramma 2026–2027".

## Block structure (in order)

1. **Intro paragraph** — one or two sentences: what this is + that it's grounded in the city's plan.
2. **Bookmark** block to the strategic plan URL (or a paragraph link if bookmark unsupported).
3. **Callout (🎯, blue/purple)** — the **SMART objective** in one sentence (baseline → target, by date,
   advancing theme). Bold the numbers.
4. **Heading 2 — Insights** then a **bulleted list**; prefix each bullet with its source in bold:
   **Strategic plan / Planhat / Document / Meeting notes** — followed by the insight and a small ref.
   (Or use a 2-column simple table: Source | Insight.)
5. **Heading 2 — Strategic cascade**, with a short caption "strategic initiative → policy objective →
   key project". For each **initiative**: a **Heading 3** (the theme), then a **bulleted list** of its
   projects as: `**[project]** — [policy objective]` and a coloured inline tag/emoji
   (★ policy priority / ◇ mapped for participation). Add a callout if an initiative has no project yet.
6. **Heading 2 — 12-month timeline** — a **table** (or inline database). Columns: Project · Theme ·
   Start month · Duration · Type · Reason · Expected reach. One row per project, in schedule order.
7. **Heading 2 — Projects in detail** — one **toggle** per project (toggle title = project name).
   Inside each toggle: Policy objective · What we'll do (phases + methods) · Why it fits [city] ·
   Expected reach · Influence · Proven elsewhere (case study + link).
8. **Divider**, then a small footer paragraph: "Go Vocal · grounded in [plan title] · prepared [date]".

## Formatting tips
- Use callouts for the objective and any coverage gaps (coloured background for emphasis).
- Use a real Notion **table** for the timeline so it sorts/reads cleanly; keep cells short.
- Toggles keep the page compact while preserving full per-project detail.
- Bold key numbers (baseline, target, %, reach). Avoid em dashes if the user's style prefers hyphens.
- Tag colours: priority = red/pink, participation = blue (use emoji ★ / ◇ if block colour isn't available).
- After creating, return the page URL and a 2–3 line summary (objective, #projects, standout flagship).

## If a target Notion location is known
Place the page under the relevant team/space (e.g. a "City plans" or account page) if the user names
one; otherwise create at the workspace root and share the link.
